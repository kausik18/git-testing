# GreenLeaf Plant Shop (Vue + Vite)

Site 5 of the SEO test-site suite. A fictional Seattle houseplant shop, built as a
**client-side rendered single-page app** (CSR SPA).

| | |
|---|---|
| Framework | Vue 3.5 + Vue Router 5.4 + @unhead/vue 3.4, built with Vite 8.3, TypeScript 6.0 (type-checked with vue-tsc 3.3) |
| Head management | `@unhead/vue` `useHead()`, wrapped in `usePageSeo()` in `src/seo.ts` |
| Rendering mode | CSR SPA: the server always returns the same `index.html`; all content and per-route head tags are rendered by JavaScript |
| Port | **3005** (dev and preview, `strictPort`) |
| Node | 22.18+ (the sitemap script imports `src/data.ts` using Node's built-in type stripping) |

TypeScript is pinned to 6.0.x because vue-tsc needs the JavaScript compiler API, which the
native TypeScript 7 package does not ship.

## Commands

```bash
npm install
npm run dev       # dev server on http://localhost:3005 (regenerates robots.txt/sitemap.xml first)
npm run build     # type-check (vue-tsc) + production build to dist/ (regenerates robots.txt/sitemap.xml first)
npm run preview   # serve dist/ on http://localhost:3005
```

## SITE_URL

Canonical, Open Graph, JSON-LD, robots.txt and sitemap URLs are built from `VITE_SITE_URL`
(default `http://localhost:3005`). Set it in the environment or in a `.env` file (see `.env.example`):

```bash
VITE_SITE_URL=https://greenleaf.example npm run build
```

`robots.txt` and `sitemap.xml` are static files in `public/`, generated by
`scripts/gen-sitemap.mjs` (runs as `predev` / `prebuild`) from the `sitemapRoutes` list in
`src/data.ts`, the same data the pages render from.

### SPA notes

- `index.html` contains a default `<title>` and meta description for crawlers that do not run
  JavaScript. They are removed on boot (`src/main.ts`), and each route then sets its own title,
  description, canonical, Open Graph, Twitter, robots and JSON-LD tags in `<head>` via @unhead/vue.
- `<RouterView>` is keyed by path, so every navigation remounts the page and replaces its head entry.
- Vite's SPA history fallback serves `index.html` for every deep link in dev and preview.
- **404:** a static SPA cannot send a real HTTP 404. Unknown paths return **HTTP 200** with the
  client-side "Page not found" view, which sets `<meta name="robots" content="noindex, follow">` and
  has no canonical (a soft 404). This is a limitation of the rendering mode, not an intentional defect.

## Intentional SEO issues

These defects are deliberate. Everything else is intended to be clean. All three are only visible
after JavaScript runs.

| # | Issue | URL | Where in code |
|---|---|---|---|
| 1 | Missing `<link rel="canonical">` (all other head tags present) | `http://localhost:3005/faq` | `src/pages/Faq.vue` (`canonical: null`) |
| 2 | Image without `alt` attribute (the "More photos" gallery image `/images/plant-fiddle-leaf-detail.svg`; it still has width/height) | `http://localhost:3005/plants/fiddle-leaf-fig` | `src/data.ts`, `products[1].gallery[0]` |
| 3 | Non-descriptive link text: "click here" linking to `/blog/beginner-guide-to-watering-houseplants` (in the "New to plant parenthood?" section) | `http://localhost:3005/` | `src/pages/Home.vue` |
