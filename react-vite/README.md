# PixelForge Design Agency (React + Vite)

Site 3 of the SEO test-site suite. A fictional Portland design agency, built as a
**client-side rendered single-page app** (CSR SPA).

| | |
|---|---|
| Framework | React 19.3 + React Router 7.18 (`react-router`), built with Vite 8.3, TypeScript 7.0 |
| Head management | React 19 native metadata hoisting (`<title>`, `<meta>`, `<link>` rendered per route in `src/components/Seo.tsx`) |
| Rendering mode | CSR SPA: the server always returns the same `index.html`; all content and per-route head tags are rendered by JavaScript |
| Port | **3003** (dev and preview, `strictPort`) |
| Node | 22.18+ (the sitemap script imports `src/data.ts` using Node's built-in type stripping) |

## Commands

```bash
npm install
npm run dev       # dev server on http://localhost:3003 (regenerates robots.txt/sitemap.xml first)
npm run build     # type-check (tsc) + production build to dist/ (regenerates robots.txt/sitemap.xml first)
npm run preview   # serve dist/ on http://localhost:3003
```

## SITE_URL

Canonical, Open Graph, JSON-LD, robots.txt and sitemap URLs are built from `VITE_SITE_URL`
(default `http://localhost:3003`). Set it in the environment or in a `.env` file (see `.env.example`):

```bash
VITE_SITE_URL=https://pixelforge.example npm run build
```

`robots.txt` and `sitemap.xml` are static files in `public/`, generated by
`scripts/gen-sitemap.mjs` (runs as `predev` / `prebuild`) from the `sitemapRoutes` list in
`src/data.ts`, the same data the pages render from.

### SPA notes

- `index.html` contains a default `<title>` and meta description for crawlers that do not run
  JavaScript. They are removed on boot (`src/main.tsx`), and each route then renders its own title,
  description, canonical, Open Graph, Twitter and robots tags, which React 19 hoists into `<head>`.
- JSON-LD `<script type="application/ld+json">` blocks are rendered at the top of `<main>`
  (React 19 does not hoist inline scripts), which search engines accept.
- Vite's SPA history fallback serves `index.html` for every deep link in dev and preview.
- **404:** a static SPA cannot send a real HTTP 404. Unknown paths return **HTTP 200** with the
  client-side "Page not found" view, which sets `<meta name="robots" content="noindex, follow">` and
  has no canonical (a soft 404). This is a limitation of the rendering mode, not an intentional defect.

## Intentional SEO issues

These defects are deliberate. Everything else is intended to be clean. All three are only visible
after JavaScript runs.

| # | Issue | URL | Where in code |
|---|---|---|---|
| 1 | `<title>` longer than 70 characters (102 chars: "Website Design and Development Services for Growing Businesses and Startups \| PixelForge Design Agency") | `http://localhost:3003/services/web-design` | `src/data.ts`, `services[1].title` |
| 2 | Two `<h1>` elements ("About PixelForge" and "A small studio with a big portfolio") | `http://localhost:3003/about` | `src/pages/About.tsx` |
| 3 | Canonical points to the home page (`<link rel="canonical" href="http://localhost:3003/">`) instead of the page itself | `http://localhost:3003/blog` | `src/pages/Blog.tsx` |
